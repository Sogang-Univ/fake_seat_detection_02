좋아. 이제 **CPU vs PL의 속도와 전력 효율을 동일 조건에서 직접 비교할 수 있는 데이터가 완성됐어.** 결과는 PL 쪽이 상당히 명확하게 우세해.

| 지표                  |   CPU 전처리 |         PL 전처리 |        PL 효과 |
| ------------------- | --------: | -------------: | -----------: |
| Latency             | 24.708 ms |   **7.463 ms** | **69.8% 감소** |
| Throughput          | 40.47 FPS | **134.00 FPS** |    **3.31×** |
| SOM 평균전력            |   5.797 W |    **5.268 W** |  **9.1% 감소** |
| Idle 대비 추가전력        |   0.907 W |    **0.378 W** | **58.3% 감소** |
| FPS/W               |      6.98 |      **25.44** |    **3.64×** |
| 전체 SOM Energy/frame |  143.2 mJ |    **39.3 mJ** | **72.5% 감소** |
| 추가 Energy/frame     |   22.4 mJ |    **2.82 mJ** | **87.4% 감소** |

즉 네가 아까 걱정했던 **“FPGA를 썼는데 CPU보다 느리거나 전력도 별 차이가 없으면 의미 없는 것 아닌가?”**라는 부분은 현재 실험으로 꽤 강하게 해소됐어.

### 1. 속도

동일한 작업을 수행했을 때:

```text
CPU : 24.708 ms/frame
PL  :  7.463 ms/frame
```

따라서:

```text
Speedup
= 24.708 / 7.463
≈ 3.31×
```

이고 latency는 약 **69.8% 감소**했어.

### 2. 절대 전력도 PL이 더 낮음

Idle은:

```text
4.890 W
```

CPU 전처리 수행 중:

```text
5.797 W
```

PL 전처리 수행 중:

```text
5.268 W
```

이니까 PL은 더 빠른데도 전체 SOM 전력이:

```text
5.797 → 5.268 W
```

로 **약 0.529 W, 9.1% 낮아졌어.**

이건 꽤 좋은 결과야. PL이 3.3배 빨라지는 대신 전력을 더 소비한 것도 아니고, **오히려 평균 SOM 전력까지 감소**했으니까.

### 3. Idle을 빼면 차이가 더 커짐

전처리 작업 때문에 추가로 소비된 전력을 계산하면:

```text
CPU:
5.797 - 4.890
= 0.907 W
```

```text
PL:
5.268 - 4.890
= 0.378 W
```

즉 workload에 의한 추가 전력만 보면:

```text
0.907 W → 0.378 W
```

로 **약 58.3% 감소**했어.

다만 이 `idle-subtracted power`는 보조 지표로 사용하는 게 좋아. 보드 전체의 static power와 각 rail의 상호작용 때문에 정확한 “CPU만의 전력”, “PL만의 전력”이라고 해석하면 안 돼. 대신 **동일 firmware, 동일 보드, 동일 조건에서 workload 증가분을 비교한 값**이라고 표현하면 정확해.

### 4. 프로젝트에서 가장 강한 지표는 FPS/W

CPU:

```text
40.47 FPS / 5.797 W
≈ 6.98 FPS/W
```

PL:

```text
134.00 FPS / 5.268 W
≈ 25.44 FPS/W
```

따라서:

```text
25.44 / 6.98
≈ 3.64×
```

즉 **PL의 처리량 대비 전력 효율이 CPU보다 약 3.64배 높아.**

이건 가속기 프로젝트에서 상당히 좋은 핵심 성과 지표야.

### 5. 프레임 하나 처리하는 데 필요한 에너지

전체 SOM 기준으로 보면 CPU는:

```text
5.797 W / 40.47 FPS
≈ 0.1432 J/frame
= 143.2 mJ/frame
```

PL은:

```text
5.268 W / 134 FPS
≈ 0.0393 J/frame
= 39.3 mJ/frame
```

따라서 프레임당 에너지가:

```text
143.2 → 39.3 mJ/frame
```

으로 **약 72.5% 감소**했어.

이 지표도 아주 좋아. 단순히 “PL 전력이 조금 낮았다”보다:

> 같은 한 프레임의 전처리를 완료하는 데 필요한 에너지가 약 72.5% 감소하였다.

라고 설명할 수 있기 때문이야.

## 지금 프로젝트에서 주장할 수 있는 핵심 성과

이제 보고서에서는 꽤 자신 있게 다음처럼 정리할 수 있어.

> 동일한 640×480 BGR 입력에 대해 ROI crop, 640×640 resize, RGB 변환 및 DPU 입력용 INT8 양자화를 수행하도록 CPU와 PL 전처리 경로를 동일 조건에서 비교하였다. CPU 구현은 평균 24.708 ms, PL 구현은 7.463 ms로 측정되어 PL이 약 3.31배의 가속과 69.8%의 latency 감소를 달성하였다. 또한 SOM 평균 전력은 CPU 수행 시 5.797 W에서 PL 수행 시 5.268 W로 약 9.1% 감소하였다. 이에 따라 처리 효율은 6.98 FPS/W에서 25.44 FPS/W로 약 3.64배 향상되었으며, 프레임당 에너지는 143.2 mJ에서 39.3 mJ로 약 72.5% 감소하였다.

여기에 기능 검증 결과도 같이 붙일 수 있어:

```text
CPU ↔ PL 출력 비교
Exact match      = 96.73%
Within ±1        = 100%
Max abs diff     = 1
```

그래서 최종적으로는:

**성능:** 3.31× 향상
**평균 전력:** 9.1% 감소
**FPS/W:** 3.64× 향상
**Energy/frame:** 72.5% 감소
**출력 정확성:** 100%가 ±1 이내

라는 아주 깔끔한 결과가 나온 거야.

다만 보고서용 최종 수치로 확정하기 전에 **CPU와 PL 실험을 각각 3회 정도 반복해서 평균±표준편차를 내는 것**을 권장해. 지금 1회 측정만으로도 경향은 매우 크고 명확하지만, 반복 측정까지 하면 교수님이 “한 번 측정한 우연 아니냐”고 물어도 훨씬 강하게 대응할 수 있어.
