맞아. 네가 말한 건 **xclbin 만드는 Makefile/config가 아니라, KV260 보드에서 실제로 돌렸던 crop+resize 실행 코드** 쪽이야.

그 코드 기준으로 보면, 이번 `crop + resize + PL quantization` 버전 때문에 구조적으로 바꿔야 하는 핵심은 **출력 처리 부분**이야.

기존 보드 코드는 대략 이런 흐름이었어:

```text
카메라 BGR 프레임
   ↓
C++ wrapper에서 RGBx 32-bit로 Packing
   ↓
H2D
   ↓
HLS crop + resize
   ↓
RGBx 32-bit 640×640 출력
   ↓
D2H
   ↓
Unpacking
   ↓
Python/C++에서 INT8 quantization
   ↓
DPU input
```

즉 HLS 출력이 예전에는:

```text
640 × 640 × 4 byte
= 1,638,400 bytes
```

의 RGBx 영상이었어.

그런데 지금 HLS는 내부에서 quantization까지 끝내니까:

```text
카메라 BGR 프레임
   ↓
RGBx Packing
   ↓
H2D
   ↓
HLS
 ├ crop
 ├ resize
 ├ quantization
 └ RGB INT8 packing
   ↓
INT8 RGB 640×640×3
   ↓
D2H
   ↓
DPU input으로 복사
```

가 되는 거야.

따라서 **보드에서 쓰던 crop+resize 코드에서 구조적으로 바뀌어야 하는 건 3개**야.

1. **출력 버퍼 크기/형식 변경**

기존:

```cpp
640 * 640 * 4
```

즉 RGBx uint8 출력이었다면,

현재는:

```cpp
640 * 640 * 3
```

즉 DPU용 RGB INT8 출력이야.

크기로 보면:

```text
기존: 1,638,400 bytes
현재: 1,228,800 bytes
```

야.

2. **기존 Unpacking 삭제**

예전 wrapper에서는 HLS에서 128-bit word를 받아서 다시:

```text
R,G,B,X
R,G,B,X
...
```

형태의 numpy/OpenCV 이미지로 풀었지.

지금은 HLS 출력 자체가 메모리에:

```text
R0 G0 B0 R1 G1 B1 R2 G2 B2 ...
```

형태로 이미 연속 저장돼.

그러니까 기존의:

```text
128-bit word
→ 32-bit pixel
→ R/G/B 추출
→ numpy 640×640×3
```

같은 **unpacking 과정이 필요 없어.**

그냥 출력 메모리의 앞:

```text
1,228,800 bytes
```

를 그대로 INT8 tensor로 보면 돼.

3. **PS quantization 삭제**

기존에는 HLS 출력 후에:

```python
quant = np.rint(rgb * 64.0 / 255.0).astype(np.int8)
```

같은 처리가 필요했어.

지금은 FPGA에서 이미:

```cpp
(value + 2) >> 2
```

로 quantization까지 완료하니까 이 단계도 없어져.

그래서 최종적으로 기존 보드 코드는 이렇게 바뀌는 게 핵심이야:

```text
기존
Packing
→ H2D
→ HLS crop+resize
→ D2H
→ Unpacking
→ Quantization
→ DPU
```

에서

```text
변경
Packing
→ H2D
→ HLS crop+resize+quant
→ D2H
→ DPU input으로 memcpy
→ DPU
```

로 단순해져.

그리고 **입력 쪽 Packing은 그대로 유지해야 해.** 현재 HLS 입력은 여전히:

```text
32-bit RGBx
[7:0]   R
[15:8]  G
[23:16] B
[31:24] X
```

를 기대하니까 기존 입력 packing 구조는 바꿀 필요 없어.

즉 가장 짧게 말하면:

> **보드에서 돌리던 crop+resize 코드에서 입력부는 그대로 두고, 출력부의 `RGBx unpacking + PS quantization`을 삭제하고, HLS가 내놓는 640×640×3 INT8 데이터를 바로 DPU 입력으로 넘기도록 수정해야 해.**

다음 단계에서 우리가 실제로 해야 하는 건 **예전에 보드에서 쓰던 `hls_crop_wrapper.cpp`를 이 새 출력 형식에 맞게 수정하는 것**이야. 그 코드를 기준으로 어디를 지우고 어디를 바꿔야 하는지 정확히 잡아줄 수 있어.
